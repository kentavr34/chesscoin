## Как читать diff

```bash
docker exec chesscoin_backend sh -lc \
  'npx prisma migrate diff --from-url $DATABASE_URL --to-schema-datamodel prisma/schema.prisma --script'
```

Он показывает «как привести БД к схеме», а не «что забыли применить».
Всё, чего нет в `schema.prisma`, он предлагает снести — включая чужое.

## Разбор: что НЕ применено и почему

### 1. `DROP TABLE` шести таблиц — 🚫 никогда

| Таблица | Строк | Чья |
|---|---|---|
| `claudia_memory` | 0 | Claudia |
| `claudia_rag_queue` | 0 | Claudia |
| `claudia_tasks` | 0 | Claudia |
| `conversations` | 3 | Claudia |
| `task_buffer` | 2 | Claudia |
| `user_sessions` | 1 | требует выяснения — легаси ChessCoin или чужое |

Их нет в `schema.prisma`, поэтому Prisma считает их лишними. Они не мешают:
Prisma не трогает таблицы, которых не знает.

### 2. `DROP COLUMN` — 🚫 не удаляем данные

| Колонка | Данные | Код | Решение |
|---|---|---|---|
| `users.countryCode` | **7 значений из 88** | в `schema.prisma` у модели `User` поля нет; в коде `countryCode` относится к `Country`/`Clan` | легаси, но данные живые — оставить, вопрос Кенану |
| `countries.commanderUserId` | 0 значений | 0 упоминаний в коде | пусто и не используется, но правило «ничего не удалять» — оставить |
| `trade_orders.executedAt / priceUsd / totalUsd` | по 10 значений | заменяются на `price`/`filledAt` в схеме | часть задачи по бирже, см. п.3 |

### 3. `trade_orders`: text → enum + `price NOT NULL` — ⏳ отдельная задача

Схема ждёт enum-типы (`TradeOrderType`, `TradeOrderCurrency`, `TradeOrderStatus`)
и колонку `price DOUBLE PRECISION NOT NULL`, в проде — `text` и старые
`priceUsd`/`totalUsd`.

Хорошая новость: значения в 10 существующих строках **уже совпадают** с будущими
enum'ами (`BUY|SELL` / `TON|STARS` / `OPEN`), конверсия пройдёт без потерь.
Но `ADD COLUMN price NOT NULL` на непустой таблице упадёт без `DEFAULT` или
предварительного заполнения из `priceUsd`.

Делать вместе с работой над биржей и с согласованием Кенана — это изменение
экономической подсистемы, а не техническая уборка.

### 4. `DROP INDEX` шести индексов — 🚫 не трогаем

`clan_wars_*`, `country_members_countryid_contribution_idx`, `tasks_taskType_idx`,
`users_isMonthlyChampion_idx`. Лишние индексы никому не мешают, их удаление —
косметика ради «чистоты diff».

### 5. Мелкие `ALTER COLUMN ... DROP/SET DEFAULT` — 🚫 не трогаем

`updatedAt DROP DEFAULT` и подобное. Поведение приложения не меняют,
риск на живой базе не оправдан.

## Правило на будущее

1. Новая модель или колонка → **отдельная аддитивная миграция** в
   `backend/prisma/migrations/`, применяется и регистрируется в `_prisma_migrations`.
2. Удаление чего-либо в БД → только с явным решением Кенана и после архива.
3. После каждой миграции — пересчитать размер дрейфа и обновить таблицу «Состояние»
   в этом файле. Рост дрейфа без записи здесь = кто-то правил схему мимо миграций.

## Архивные таблицы `archive_*` — не дрейф

При уборке данных по решению Кенана строки сначала копируются в таблицу
`archive_<что>_<дата>`, и только потом удаляются (правило «ничего не удаляем
без архива»). В `schema.prisma` их нет и быть не должно — Prisma честно
предлагает их удалить, но это намеренное расхождение.

Поэтому страж считает дрейф командой `scripts/check_schema_drift.sh`,
которая отбрасывает строки с `archive_`. Порог — 104 строки.

Поймано 30.07: страж поднял тревогу сразу после архивации ордеров биржи.
Тревога была верной по форме и ложной по сути — инструмент научен различать.
