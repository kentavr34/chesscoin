2. **Тот ли объект проверен?** Не соседний файл, не похожая функция, не другой
   экран. Назвать конкретно: какой файл, какой коммит, какой экран, какой аккаунт.
3. **Виден ли результат в проде?** Хеш `index-*.js` сменился, контейнер `Up`,
   в логах за минуту нет `error`, эндпоинт отвечает.

## Порядок

1. **Прогон эталона:** `python project_management/tools/regression.py` — полный
   вывод в отчёт. Провалы называть провалами.
2. **Проверка глазами игрока:** пройти сценарий целиком в Telegram, не первый экран.
3. **Отчёт покомпонентный.** По каждому пункту задачи: сделано / не сделано /
   сделано частично — и **чем доказано**. Умолчание считается ложью.
4. **`public.claudia_learned_solutions`** (project='chesscoin'): что сломалось →
   КОРЕНЬ → что помогло. Неудачные попытки тоже записывать — они экономят время потом.
5. **`chesscoin_pm.agent_mistakes`**: если ошиблась сама — ошибка, корень и правило,
   которое её закрывает. Правило без механизма не работает — указать механизм.
6. **`chesscoin_pm.regression_cases`**: каждый вылеченный дефект добавляется в эталон
   **в тот же день**. Строка ✅ в `TODO_FIXES.md` без записи в эталон = незакрытый дефект.
7. **`registry/FILE_REGISTRY.md`**: какие файлы менялись, ±строк, новые/перемещённые —
   по `git diff --stat`, а не по памяти.
8. **`registry/OPERATIONS_LOG.md`**: хронология сессии (что, когда, зачем, результат).
9. **`registry/PROJECT_MANAGEMENT.md`**: отметить выполненное, обновить открытое.
10. **git commit + push** в ветку; мёрдж в `main` — решение Кенана.
11. **Итог в память:** запись в `claudia_memory.dialog_history` (project='chesscoin')
    и в локальный `docs/history/HISTORY.md`.
12. **Закрыть регистрацию входа:**
    ```sql
    UPDATE chesscoin_pm.session_log SET closed_at=now(), summary='...' WHERE id=<id>;
    ```
