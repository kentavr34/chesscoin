# 🔬 ВОРОТА ДИАГНОЗА — как объявлять корень проблемы

> Правило существует потому, что в ChessCoin один и тот же класс ошибки повторялся
> многократно: объявляла причину по предположению, чинила симптом, докладывала
> «исправлено», и через день Кенан находил то же самое.

## Правило

**Перед словом «корень» / «причина в том, что…» — прогнать ворота:**

```bash
python project_management/tools/why.py "батлы"
```

Ворота печатают три вещи:
1. **Боевой путь подсистемы** — чем эта штука проверяется в реальности
   (`chesscoin_pm.prod_path_registry`);
2. что уже решали по теме и какие корни назывались
   (`claudia_learned_solutions` project='chesscoin');
3. мои ошибки по теме и правила, которые их закрывают (`chesscoin_pm.agent_mistakes`).

**Диагноз объявляется только после прохода боевым путём с боевыми параметрами.**
Проверка соседней функции, юнит-тест или desktop-браузер доказательством не являются.

## Цикл диагностики (обязателен при повторе бага)

1. **≥3 гипотезы.** Одна гипотеза — это не диагностика, это догадка.
2. **Каждая проверяется данными:** лог, запрос в БД, сетевой ответ, скрин.
3. **Узкий фикс** по подтверждённой гипотезе.
4. **e2e-проверка** на уровне игрока.
5. Не подтвердилось — **вернуться к п.1 с новым набором гипотез**.
   Повторный фикс той же непроверенной гипотезы запрещён.

## Реестр боевых путей (`chesscoin_pm.prod_path_registry`)

| Подсистема | Боевой путь | Ловушка |
|---|---|---|
| Mini App | Telegram на **телефоне** → @chessgamecoin_bot → Mini App | десктоп-браузер не воспроизводит initData и мобильные баги логина |
| Backend API | `docker exec chesscoin_backend sh -lc "wget -qO- http://localhost:3000/health"` | публичного `/api/health` нет — снаружи 404, это не поломка |
| Игровой сокет | реальная партия двумя аккаунтами + зритель | unit-тест `formatSession` не ловит переворот доски |
| Бот | `docker logs chesscoin_bot --tail 30`, живая команда `/start` | ошибки уведомлений в логе маскируют отсутствие ответа на команды |
| БД | `docker exec chesscoin_postgres psql -U chesscoin -d chesscoin` | pgbouncer (6432) и postgres (5432) — разные пути |
| Redis | `redis-cli -n 1` | без `-n 1` всегда «пусто» |
| Деплой | `git pull` в `/opt/chesscoin` + `docker compose up -d --build` | адрес прода менялся дважды — брать из резолва домена |
| Фронт-бандл | `curl -s https://chesscoin.app/ \| grep -o "index-[A-Za-z0-9]*\.js"` | `last-modified` может не смениться — сверять хеш |
| Cron | `docker logs chesscoin_backend --since 2h \| grep Cron` | падение cron глушится и выглядит как «функция не работает» |

Подсистемы нет в реестре — **сначала найти её боевой путь**, внести в реестр,
и только потом диагностировать.

## Почему правила было мало

«Проверяй прежде чем говорить готово» уже стояло в CLAUDE.md — и всё равно
нарушалось, потому что старт сессии показывает память один раз, а диагноз
рождается часами позже. Правило без механизма, срабатывающего **в момент
диагноза**, не работает. Ворота — этот механизм.
