# 📚 ИНВЕНТАРИЗАЦИЯ И РЕЕСТР ФАЙЛОВ — принцип библиотеки

> Реестр — исчерпывающий источник правды о том, что есть в контурах проекта.
> Если файл есть на диске, но его нет в реестре — сигнал: либо забыли записать,
> либо он чужой.
>
> **Особенность ChessCoin:** на проде рядом живут ещё два проекта. Инвентаризация
> обязана уметь их различать и никогда не трогать.

## Что делает инвентаризация

```bash
python project_management/tools/inventory.py
```

1. Обходит контуры, по каждому файлу: путь, размер, дата, sha256(16), тип.
2. Пишет снимок в `chesscoin_pm.file_inventory` и отчёт в `registry/FILE_REGISTRY.md`.
3. Сравнивает со вчерашним снимком и отдельно помечает:
   - **новые файлы** — появились сами, потенциально чужие;
   - **исчезнувшие** — особенно опасно для сборочных артефактов;
   - **изменённые** — по sha, а не по дате;
   - **расхождение прод ↔ репо** — файл есть на проде, но не в git (или наоборот).
4. Отдельно проверяет исполняемые артефакты (`.sh`, `.js`, `.py` вне `src`) —
   они пропадают незаметнее всего.

## Правило архива

Ничего не удаляем сразу. Лишнее переносится в `/opt/chesscoin-archives/<дата>_<что>/`
с записью в реестр: откуда, почему признано лишним, кем. Физическое удаление —
только по решению Кенана.

## Регистрация обращений

Любое **изменение** (мной, скриптом, кроном, деплоем) регистрируется:
`chesscoin_pm.operations_log` через `tools/note.py`. Чтение регистрировать не обязательно.
