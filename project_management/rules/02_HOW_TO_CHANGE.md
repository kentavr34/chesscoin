# 🛠 ИНСТРУКЦИЯ 2 — ИНИЦИАЦИЯ И ПОРЯДОК ИЗМЕНЕНИЙ

> Принцип: **сделай лучше или не трогай.** Целая система важнее одной правки.
> Эта инструкция закрывает самый дорогой класс аварий ChessCoin: «пришёл чинить
> одно — сломал соседнее одобренное».

## 0. Разрешение на изменение

Прежде чем менять — ответить себе на три вопроса:

1. **Кенан просил именно это?** Не «похожее», не «заодно». Дословно.
2. **Есть ли утверждённый шаблон у того, что я трогаю?** → `09_TEMPLATES.md`.
   Есть — правка = возврат к шаблону, а не новая версия.
3. **Это правка или архитектура?** Архитектура, экономика, схема БД, состав
   механик — **стоп, спросить Кенана**.

Обнаружила по дороге другую проблему — **записать в `registry/TODO_FIXES.md`
и продолжить свою задачу**. Не чинить молча: 25.04 три дня ушли на «чинила свой
же косяк», пока Кенан ждал фронтенд.

## 1. Порядок любой правки

1. **Измерь исходное состояние.** Скрин/лог/вывод команды — зафиксируй ДО.
2. **Найди корень, а не симптом.** Перед словом «корень» — `07_DIAGNOSIS.md`.
   Гипотеза без данных причиной не становится. Повторный фикс той же гипотезы запрещён.
3. **Правка хирургическая:** конкретная строка/функция. Не переписывать файл
   целиком, не «причёсывать» форматирование, не трогать соседние компоненты.
4. **Одна фаза — полностью готова** перед следующей.
5. **Ветка, а не main.** Продуктовые правки — отдельная ветка, PR, мёрдж за Кенаном.
6. **Проверь сборку** сразу после правки (`tsc`/`npm run build` — что применимо).
7. **Деплой:** push в `main` → `ssh root@45.67.216.36 "cd /opt/chesscoin && git pull &&
   docker compose up -d --build backend frontend"`. Перед ssh — резолв домена.
8. **Измерь снова тем же способом, что и в п.1.** Разницу — в отчёт.
9. **Запиши:** `note.py` по ходу, затем `OPERATIONS_LOG.md`, `claudia_learned_solutions`,
   а вылеченный дефект — в `regression_cases` (`08_REGRESSION.md`).

## 2. Правки в БД

- Схема меняется **только миграцией Prisma**, применяется `prisma migrate deploy`.
- Ручной `ALTER TABLE` на проде = хотфикс, который **в тот же день** оформляется
  миграцией в репо. Иначе следующий reset всё откатит.
  *(14.05: ручные ALTER → enum `TransactionType` 31 против 36 в схеме → cron турниров
  падал каждый час, призы не выдавались.)*
- Удаление данных — только с подтверждением Кенана. Вместо DELETE — смена статуса.

## 3. Правки на сервере

- Любой ручной фикс проверяется вопросом: **«переживёт ли это hard reboot?»**
  Нет — оформить в `docker-compose` (healthcheck, `depends_on: service_healthy`),
  в entrypoint или в systemd-unit.
- Прямые правки файлов на проде запрещены, кроме hotfix — и тогда обязательна
  фиксация тем же днём в репо.
- Каталоги и контейнеры Claudia и Jobus не трогать никогда.

## 4. Чего не делать никогда

- менять утверждённый шаблон (иконку, шрифт, цвет, расположение) без явной просьбы;
- «упрощать» одобренный компонент;
- откатывать то, что уже частично починено, — доводить, а не откатывать;
- расширять область работ без спроса;
- эмодзи в UI Mini App — только SVG-иконки;
- `window.innerWidth` — только CSS media queries;
- докладывать результат, не увидев его тем же путём, что и Кенан.

## 5. Когда остановиться и спросить

- изменение архитектуры, экономики, баланса, схемы БД;
- удаление файлов, данных, контейнеров, веток;
- траты (платные ключи, TON-операции);
- всё, что затрагивает живых игроков в момент, когда они играют.
