# 🧠 PROJECT MANAGEMENT — управляющий контур ChessCoin

> **Назначение:** это «мозг» работы над проектом, отдельный от самого продукта.
> Продукт (бот, игра, сервер) живёт своей жизнью; здесь — правила, память, учёт
> и защита от повторения ошибок.
>

> проектом из 994 и адаптировать под ChessCoin. Не копия — переосмысление
> под три системы этого проекта и под его собственную историю ошибок.

## Три системы проекта (не путать)

| Система | Что это | Где живёт |
|---|---|---|
| **Бот** | @chessgamecoin_bot: запуск Mini App, уведомления, подписчики, посты в канал | `bot/`, контейнер `chesscoin_bot` |
| **Игра** | механика, экономика, движок, сокеты, серверная архитектура, UI | `backend/`, `frontend/`, `stockfish/`, `nginx/` |
| **Управление** | как мы ведём работу: инструкции, реестр, история, память ошибок | **эта папка** + БД `chesscoin_pm` |

Третья система не трогает первые две. Первые две не диктуют правила третьей.

## Инструменты

| Скрипт | Что делает | Когда |
|---|---|---|
| `tools/session_start.py` | собирает картину: контейнеры, изменения за сутки, память, дефекты, эталон; регистрирует вход | каждый старт |
| `tools/why.py <тема>` | ворота диагноза: боевой путь + что уже решали + мои ошибки по теме | **перед словом «корень»** |
| `tools/inventory.py` | реестр всех файлов контуров, новые/изменённые/исчезнувшие, чужое | ежедневно / при подозрении |
| `tools/regression.py` | прогон эталона достигнутого, тревога только на пропажу работавшего | после фикса и ежедневно |
| `tools/note.py "текст"` | запись в журнал операций ПО ХОДУ работы | по ходу сессии |
| `tools/pm_schema.sql` | DDL управляющего контура (уже применён на проде) | при переносе/восстановлении |

Все скрипты работают с ПК (через ssh к проду) — отдельная установка на сервер не нужна.

## Память проекта — схема `chesscoin_pm` (PostgreSQL на 45.67.216.36)

> **Независима от Claudia.** Вся память проекта лежит в одной схеме без внешних
> связей наружу: при переносе ChessCoin на отдельный сервер она уезжает вместе
> с проектом одним куском (`pg_dump -n chesscoin_pm`) и поднимается в любой базе.
> Требование Кенана 29.07.2026.

| Таблица | Что | Зачем |
|---|---|---|
| `chat_history` | **21 731 сообщение** диалога с 03.04.2026 — своя копия | контекст без выдумывания и без чужой базы |
| `problem_solutions` | технические проблема → КОРЕНЬ → решение | не чинить дважды одно и то же |
| `agent_mistakes` | управленческие промахи исполнителя → корень → правило | не повторять свои ошибки |
| `change_log` | **178 коммитов**: что и когда реально менялось в коде | история модификаций отдельно от git |
| `prod_path_registry` | подсистема → боевой путь → ловушка | чтобы тест шёл тем же путём, что прод |
| `regression_cases` / `regression_runs` | что уже доказано работающим | чтобы достигнутое не терялось молча |
| `file_inventory` | снимки файлов контуров | чтобы чужое/мёртвое не жило незамеченным |
| `session_log` / `operations_log` | кто вошёл, зачем, что изменил | принцип библиотеки |

Копии досинхронизируются командой `python tools/sync_memory.py` (повторный запуск
безопасен — дубликаты отсекаются). Исходники в общей памяти Claudia
(`claudia_memory.dialog_history`, `public.claudia_learned_solutions`) остаются
на месте — мы их только читаем.

## Принцип

1. **Ничего по памяти — всё по факту.** Память подсказывает, где смотреть; решение принимается по данным.
2. **Сначала спроси базу, потом планируй.** Почти всё уже случалось.
3. **Не навреди.** Лучше не тронуть, чем сломать работающее.
4. **Фиксируй как библиотекарь.** Кто вошёл, что взял, что изменил, когда вернул.
5. **Задача на чтение — можно без ритуала. Задача на изменение — только после Инструкции 1.**
